## Searching Documentation (IMPORTANT)

- Use `search-docs` before changes that depend on Laravel ecosystem APIs, behavior, configuration, or version-specific syntax. Skip it for copy-only edits and other changes where package documentation is irrelevant. Reuse sufficient results already in context instead of searching again.
- Pass a `packages` array to scope results when you know which packages are relevant.
- Use multiple broad, topic-based queries: `['rate limiting', 'routing rate limiting', 'routing']`. Expect the most relevant results first.
- Do not add package names to queries because package info is already shared. Use `test resource table`, not `filament 4 test resource table`.

### Search Syntax

1. Use words for auto-stemmed AND logic: `rate limit` matches both "rate" AND "limit".
2. Use `"quoted phrases"` for exact position matching: `"infinite scroll"` requires adjacent words in order.
3. Combine words and phrases for mixed queries: `middleware "rate limit"`.
4. Use multiple queries for OR logic: `queries=["authentication", "middleware"]`.

# Inertia

- Inertia creates fully client-side rendered SPAs without modern SPA complexity, leveraging existing server-side patterns.
- Components live in `resources/js/pages` (unless specified in `vite.config.js`). Use `Inertia::render()` for server-side routing instead of Blade views.
- ALWAYS use `search-docs` tool for version-specific Inertia documentation and updated code examples.
- IMPORTANT: Activate `inertia-react-development` when working with Inertia client-side patterns.

# Inertia v3

- Use all Inertia features from v1, v2, and v3. Check the documentation before making changes to ensure the correct approach.
- New v3 features: standalone HTTP requests (`useHttp` hook), optimistic updates with automatic rollback, layout props (`useLayoutProps` hook), instant visits, simplified SSR via `@inertiajs/vite` plugin, custom exception handling for error pages.
- Carried over from v2: deferred props, infinite scroll, merging props, polling, prefetching, once props, flash data.
- When using deferred props, add an empty state with a pulsing or animated skeleton.
- Axios has been removed. Use the built-in XHR client with interceptors, or install Axios separately if needed.
- `Inertia::lazy()` / `LazyProp` has been removed. Use `Inertia::optional()` instead.
- Prop types (`Inertia::optional()`, `Inertia::defer()`, `Inertia::merge()`) work inside nested arrays with dot-notation paths.
- SSR works automatically in Vite dev mode with `@inertiajs/vite` - no separate Node.js server needed during development.
- Event renames: `invalid` is now `httpException`, `exception` is now `networkError`.
- `router.cancel()` replaced by `router.cancelAll()`.
- The `future` configuration namespace has been removed - all v2 future options are now always enabled.

## What this is
A starter kit for multi-tenant SaaS apps: the official Laravel React starter kit plus
subdomain tenancy, tenant-aware auth, memberships, roles and invitations. New apps are created
from this template and then renamed. Replace this section with the new product's context once
you start building on it.

## Stack (locked decisions)
- **Laravel + Inertia + React** via the official **React starter kit** (Inertia + React +
  Tailwind + shadcn/ui).
- **Native Laravel auth** (Fortify: login/registration/email verification/2FA/passkeys/
  password confirmation). No third-party auth provider.
- **Multi-tenancy: single-database, row-scoped** (`tenant_id` + stancl's `BelongsToTenant` global
  scope). NOT multi-DB.
- **stancl/tenancy** used **only** for subdomain identification + central/tenant domain split,
  configured single-DB with **custom columns** (real `name`/`slug` columns, not the
  schemaless `data` JSON default).
- **Subdomain-per-tenant** (`{tenant}.<APP_DOMAIN>`). Tenant `slug` = subdomain.
- **Per-subdomain login** (no shared cross-subdomain cookie). Membership is **re-verified on
  every request**: resolve tenant from subdomain, then confirm the authenticated user belongs
  to it (403 otherwise). This is the security boundary.
- **Org membership, roles, invitations owned by the app.** Roles: owner / admin / member /
  viewer (`App\TenantRole`). Rename or extend `member` to fit the product.
- **Testing: Pest**, including Playwright-backed **browser tests** (see Boost Pest notes above).

## Reserved subdomains
Tenant slugs double as subdomains, so platform hostnames must be reserved and rejected at
signup/tenant-create: by default `www`, `api`, `app`, `admin`, `mail`, `staging`. The list is
overridable via `TENANCY_RESERVED_SUBDOMAINS`; add any staging/preview hosts that share the
production apex.

## Local dev domains (macOS and Linux)
Tenant subdomains need **wildcard resolution for `*.<APP_DOMAIN>`** locally (a plain
`/etc/hosts` entry can't do wildcards). The apex domain is driven from config/env
(`APP_DOMAIN`, default `tenancy-starter.test`), so switching machines only changes local
resolution, never code.
- **macOS: Laravel Herd** — native, gives `*.test` wildcard routing + trusted local TLS out of
  the box.
- **Linux: Herd is unavailable.** Use **Valet Linux Plus** (dnsmasq + `valet secure` for TLS),
  or **dnsmasq + Caddy**, or **nip.io / sslip.io** for zero-config wildcard (http-only, no
  trusted TLS).

## Inertia routing mental model
Inertia has **no file-based routing**. `routes/web.php` (central domain) and `routes/tenant.php`
(tenant subdomains) own URLs; controllers name the React component by string.
`Inertia::render('settings/members', $data)` → `resources/js/pages/settings/members.tsx`
(lowercase `pages`, **slash** not dot). Use a controller for any page with data;
`Route::inertia()` only for dataless static pages. Subdomain + tenant middleware wrap the tenant
routes; the React side just receives props.
